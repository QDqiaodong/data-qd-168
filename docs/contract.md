# Locale bundle contract v1

A localization maintainer provides default_locale, catalogs, fallback and requested. Locale names are opaque nonblank identifiers (not a BCP-47 normalizer). Each locale maps message keys to {value,variables}; variables declares exactly the named placeholders appearing in value, with types string or integer. Repeated placeholders are legal; escaped braces are literals. Only Python-format simple identifier fields such as {name} are permitted; positional fields, attribute/index access, conversions, format specs and unmatched braces fail. Literal empty strings are valid translated messages and do not trigger fallback.

Default catalog must be nonempty. All keys and variable type maps in translations must agree with the default. Fallback is a single-parent directed graph between declared locales; default has no parent. Missing explicit parent means the default. Cycles are rejected even if their locales are not requested. Every requested locale must exist and be unique. Compilation resolves every default key along the chain, saving source_locale and a diagnostic for each fallback. This is deterministic offline resource construction, not machine translation, plural-rule evaluation or ICU MessageFormat support.

render(message, variables) validates the exact variable set and types before formatting. bool does not satisfy integer. Compilation validates the whole input before atomic publication. The sample resolves fr-CA greeting from fr, cart from fr-CA; rendering greeting with name=Ada yields Bonjour Ada.

# Reviewed history contract v2

compile_reviewed_history(data) and the locale-bundle-history CLI build per-query historical catalog views from an append-only fact log, so a maintainer can ask "which translations were approved as of business time `at`, given only the facts known up to sequence `known_seq`". The v1 message, fallback-chain, placeholder-safety and CLI protection rules are unchanged and reused.

Input fields are exactly default_locale, locales, fallback, requested, sources, translations, reviews, queries. locales holds up to 100 distinct identifiers and contains default_locale. fallback keeps the v1 single-parent rules: an omitted parent means the default locale, the default has no parent, and cycles are rejected even for unrequested locales. requested is a nonempty list of distinct declared locales.

Fact rows are exact-field objects. sources: {id,seq,effective,key,value,variables}. translations: {id,seq,effective,locale,key,source_id,value,variables} with a declared non-default locale. reviews: {seq,effective,translation_id,approved} with approved strictly boolean. queries: {id,at,known_seq}, 1 to 100 rows with distinct ids. Times and seqs are non-boolean integers; times start at 0, seqs at 1, both capped at 10^9. Source/translation ids are globally distinct, fact seqs are globally distinct across all three kinds, and input list order carries no meaning. A translation must reference a source revision with a smaller seq and repeat that revision's key and variable type map; a review must reference a translation with a smaller seq. Every message value passes the v1 placeholder safety rules, including facts no query uses. Totals: at most 10000 facts, 10000 distinct source keys. Empty default and translation values are valid.

A query sees only facts with effective <= at and seq <= known_seq; late facts carrying an earlier effective are legal, and facts outside the cutoff must not leak in, even through existing references. The current source revision of a key and the current translation revision of a (locale,key) are the visible rows with the greatest (effective,seq); a query with no visible source revision at all is invalid. A translation's review state is its visible review with the greatest (effective,seq): absent means pending, approved=false means rejected.

translation_states covers every non-default locale x every current source key, sorted by locale then key, as rows {locale,key,translation_id,review_seq,state} with nulls where no fact exists. state is missing with no visible translation, else stale_source when the selected translation's source_id differs from the current source id (this wins over review state), else the review state pending/rejected/approved. An approval authorizes only the exact translation id against the exact source revision id: a new source revision never inherits an old approval, even with identical text, and a pending/rejected/stale newer translation never resurrects an older approved one for the same locale and key.

Catalog compilation treats only translations approved within the same query as existing, then walks the v1 single-parent chain per key to the nearest available locale; the default locale serves the current source revision and needs no review. An approved empty-string translation is present and blocks fallback. Old translations only have to match the variable types of the source revision they reference, so a source type change makes them stale and resolution falls through instead of rejecting the input. Each resolved message carries value, variables, source_locale plus source_id (current source revision), translation_id and review_seq (the approving review); the last two are null for default-locale resolutions.

Output is {views:[...]} in query input order; each view is {query_id,at,known_seq,default_locale,catalogs,fallback_messages,translation_states}. catalogs contains only requested locales; fallback_messages lists requested-locale keys that fell back, sorted by locale then key. The whole input is validated before any view is emitted; any invalid fact or query fails the run with exit 2 and preserves the previous report. The 8MB read cap, duplicate JSON key and non-finite number rejection, source/output distinction, symlink refusal and atomic replacement all match v1.
